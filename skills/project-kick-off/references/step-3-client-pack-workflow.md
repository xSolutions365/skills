# Step 3 Workflow: Draft the client kick-off pack

## Objective

Produce the artefacts the client needs to get ready for week one and to understand how we will work together. Use only `client-safe` ledger entries.

## Required actions

1. Draft `client/kick-off-agenda-and-deck.md` from [../assets/templates/client/kick-off-agenda-and-deck-template.md](../assets/templates/client/kick-off-agenda-and-deck-template.md).
   - Write slide-by-slide content: a headline, three to five points, and speaker notes.
   - If a slide-generation skill or the client's deck template is available, offer to render the content with it. Do not render without the user's agreement.
2. Draft `client/engagement-plan.md` from [../assets/templates/client/engagement-plan-template.md](../assets/templates/client/engagement-plan-template.md).
   - Restate the objectives and success measures in the client's own language and figures.
   - Lay out the plan week by week, with outputs, the key sessions, and the client time each session needs.
   - Include a RACI for every deliverable and every client dependency. Use roles, not opinions about people.
3. Draft `client/prerequisites-checklist.md` from [../assets/templates/client/prerequisites-checklist-template.md](../assets/templates/client/prerequisites-checklist-template.md).
   - Start from the SoW's "what we need from you" items, then add every `dependency` row and the week-one plan's needs.
   - Give each item a purpose, a client owner (`TO CONFIRM` if unknown), and a "needed by" date worked back from the session that uses it.
   - Group items under project set-up, access to people, materials and data, and logistics.
4. Draft `client/research-access-plan.md` from [../assets/templates/client/research-access-plan-template.md](../assets/templates/client/research-access-plan-template.md) whenever the plan includes research or testing.
   - Define the participant criteria and counts from the SoW.
   - Set out a fallback ladder: target participants, then frontline or customer-service staff, then partners or brokers, then desk and observational research.
   - Offer one-to-one sessions as an alternative to group workshops for internal staff; they often surface more candid detail.
   - Set a decision date for each rung, early enough to switch without losing a week.
5. Draft `client/ways-of-working.md` from [../assets/templates/client/ways-of-working-template.md](../assets/templates/client/ways-of-working-template.md): cadence, ceremonies, channels, tools, decision-making, how feedback is given, and how scope changes are raised.
6. Draft `client/final-playback-skeleton.md` from [../assets/templates/client/final-playback-skeleton-template.md](../assets/templates/client/final-playback-skeleton-template.md).
   - Name the final audience and what each member needs to see and believe.
   - Lead with tangible outputs. Keep findings as supporting evidence rather than the main walkthrough.
   - Always include a value section (operational impact and business case) and, if the next phase is build, a starter backlog.
   - Add a `TO POPULATE` placeholder with an owner and week for each section.
7. Turn every `TO CONFIRM` the client can answer into a prerequisite row, a kick-off question, or both. Missing success baselines always become data prerequisites.
8. Keep `TO CONFIRM` markers visible in client drafts, so the team can resolve them before sending.
9. Write `client/README.md` as the pack index. Client files never reference internal files or use internal-only ID prefixes; describe internal dependencies in words.
10. List method, fidelity, and tooling choices as "to agree together" in the engagement plan, not as fixed commitments.

## Done when

- All six client files exist, or five with the research access plan explicitly not needed.
- Every prerequisite has a purpose and a needed-by date.
- The playback skeleton maps every SoW deliverable to a section.
