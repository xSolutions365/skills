# Step 5 Workflow: Write files and hand back open questions

## Objective

Leave the delivery lead with saved packs and a short, prioritised list of what to confirm next.

## Required actions

1. Confirm that every file is saved under `@OUTPUT_ROOT/internal/` and `@OUTPUT_ROOT/client/`.
2. Start the chat response with the readiness verdict. If it is `HOLD`, say that the client pack should not be sent yet, and name the questions that clear the hold.
3. Then list:
   - the open decisions from the RAID log and the engagement plan, each with an owner
   - the casting asks, if any
   - the three prerequisites with the earliest needed-by dates, each with a client owner
   - every `TO CONFIRM` item, grouped by who can answer it
4. Offer to render the kick-off deck with an available slide skill or the client's template.
5. Tell the user the packs are local drafts. Once the verdict is no longer `HOLD`, one owner (usually the delivery manager) should publish them with a documentation skill.
6. Remind the user to send the prerequisites checklist at least five working days before week one.

## Done when

- The user has file paths for both packs and a prioritised confirmation list.
